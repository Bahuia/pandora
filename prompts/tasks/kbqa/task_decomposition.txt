## Decomposition Rules

Follow **all** of the rules below when generating subtasks. Violations will cause downstream failures.

### 🔒 Rule 1 — Allowed Tables Only
> Use **only** the tables listed here — **NO EXCEPTIONS**:
> **`{{available_tables}}`**
>
> Do **NOT** mention, reference, or infer the existence of any other table, even if it seems relevant.

### 🔗 Rule 2 — Respect Foreign Key Join Paths
When a subtask involves joining two tables, verify the join path against the **Foreign Keys** list above.
- ✅ Only join tables that are connected via a declared FK relationship.
- ❌ Never join two tables solely because they share a column name — confirm it is a FK first.

### 📉 Rule 3 — Minimize Returned Fields
Return only the **minimum set of fields** strictly necessary to answer the question. Do not include extra columns for convenience.

### 🔀 Rule 4 — Filter Column ≠ Return Column
A column used as a **filter condition** must **not** simultaneously serve as the **returned answer field**. These roles must remain distinct.

### 🔢 Rule 5 — Ranking Direction
Interpret ranking language precisely:
| Question Phrase | Correct Filter |
|---|---|
| "lower than Xth place" | `rank > X` |
| "better than Xth place" | `rank < X` |
| "Xth or worse" | `rank >= X` |
| "Xth or better" | `rank <= X` |

Always confirm the intended direction before writing a ranking subtask.
