## Task 1: Schema Linking Requirements
- **Extract ALL entities from the question:** Identify every noun or entity mentioned in the question and map it to a table. Even if a word seems like a modifier (e.g., "molecules" in "single bond molecules"), it may refer to a table. Always check if entity words match table names.
- **Handle singular/plural mismatches:** Table names may be singular while the question uses plural (e.g., "molecules" → `molecule` table). Match them anyway.
- **Include required join/bridge tables:** If the question requires connecting two tables that share a column but have no direct foreign key between them, the intermediate/bridge table MUST also be included. For example, if both `atom` and `bond` have `molecule_id` but no FK connects them directly, the `molecule` table may be needed as a bridge.
- **Handle Ambiguity Explicitly:** If a phrase could map to multiple columns/tables, list ALL plausible candidates. Maintain relaxed matching criteria—actively attempt to identify at least 3 potential columns for key phrases if ambiguity exists.
- **Include Broadly Relevant Columns:** Preserve all potentially relevant columns, including those that might be used for joins, negation, or inverse logic.

## Task 2: Value Linking Requirements
- **Extract Literal Values:** Identify exact numbers, strings, or dates mentioned in the question that will be used to filter the database (e.g., "Jack", "2023", "Marketing").
- **Evaluate Literal Matches:** You must carefully consider the tables and columns suggested by any provided `literal_matching` data. If you decide **not** to use a provided literal match, you must explicitly state your reasoning in the `"thinking"` or `"ambiguities_and_risks"` section.
- **Normalize:** Note if a value might need format normalization based on the sample table content provided.

## General Requirements
- **Ensure strict JSON compliance:** Your output must be valid JSON. DO NOT include any comments (`//` or `/* */`) inside the JSON.
- **Math Formatting:** If you write any mathematical expressions in your text, you MUST use double dollar signs ($$) for ALL math (e.g., Let $$x$$ be a variable such that $$x > 0$$). NEVER use single dollar signs.

### Important: Column Name Awareness for Downstream Code Generation
- **Merge column conflicts:** When the task decomposition involves merging two tables that share column names (e.g., both have `date`, `id`, or `name`), the downstream Python code will see `_x` and `_y` suffixed column names. Note which columns may conflict so the code generator can handle them correctly.
- **Exact value formats:** When extracting values for filtering, note the exact format as shown in the sample data. Leading zeros (`'0040'` vs `40`), surrounding spaces (`' = '` vs `'='`), and case sensitivity (`'Flying'` vs `'flying'`) all matter. Report values exactly as they appear in the table content.
- **Ambiguous column semantics:** If multiple columns could represent the same concept (e.g., `position` vs `rank`, `laps` vs `lap`), explicitly note the ambiguity and explain which column is semantically correct based on the question's intent.
