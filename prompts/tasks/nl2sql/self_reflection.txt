## Logic Review Checklist

Check EACH item. For each, answer: **PASS** (no issue), **FAIL** (issue found), or **UNCERTAIN** (need more info).

### 🔴 Check 1: Filter Values Match DB Reality
Look at the **Execution State** section above. It shows actual sample values from the database.
- Are the filter values in your code EXACT matches to these sample values?
- If your code uses `'TR00_1_2'` but samples show `'TR000_1_2'` → FAIL (missing character)
- If your code uses `'Czech koruna'` but samples show `'CZK'` → FAIL (NL vs code format)
- If your code uses `'Electrical and Computer Engineering'` but samples show `'...Department'` → FAIL (incomplete)
- **If you see a mismatch, correct the filter value to match the actual DB sample.**

### 🔴 Check 2: Empty Result Risk
- If any prior DataFrame has `shape (0, N)` — the filter produced ZERO rows.
- This means the filter value is wrong, or the JOIN produced no matches.
- **If the result is empty, the filter value is almost certainly incorrect.**
- Try relaxing the filter: use `.str.contains()` instead of `==`, or use a shorter substring.

### 🔴 Check 3: JOIN / Merge Uses Correct FK
- Every `.merge()` must use columns from the **Foreign Keys** section.
- Are you merging on a generic column name like `'ID'`, `'id'`, `'name'` that exists in multiple tables?
  - If two tables share a column name but have NO FK, merging on it creates a **Cartesian product** (wrong rows).
- **Fix**: Use `left_on='FK_col', right_on='PK_col'` instead of `on='generic_name'`.

### 🔴 Check 4: Column Selection — Only Return What the Question Asks
- Does the `result` variable select EXACTLY the columns the question asks for?
- Are you returning extra columns that weren't requested?
- **Rule**: If the question asks for "the name", return only the name column, not name + city + country.

### 🔴 Check 4b: Return NAME Not ID (CRITICAL!)
- When the question asks about an entity ("Which team?", "What race?", "Which user?"), the result MUST contain the entity's **human-readable name**, NOT its internal database ID.
- **Priority order**: (1) Name/label/description column (`name`, `DisplayName`, `Title`, `location`), (2) Only if no name column exists, use the ID.
- Example: "Which user has the most orders?" → return `DisplayName`, NOT `UserId`.
- Example: "What race hosted the Grand Prix?" → return race `name`, NOT `raceId`.
- If the name is in a different table, JOIN to get it.
- **If your code returns an ID column but the question asks about an entity, this is FAIL — add a JOIN to get the name.**

### 🔴 Check 6: ORDER BY / LIMIT — Sort Before Taking Top/First/Last

- Is a date filter using the right format? (check sample values in Execution State)
