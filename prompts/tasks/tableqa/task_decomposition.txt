## Task Decomposition Requirements

- **USE ONLY THE TABLE LISTED ABOVE:** The only table you are allowed to use is `table`. All operations must be performed on this single table.

- **🔴 Subject Awareness:** If the question asks about a specific entity (e.g., "How many awards did X win?"), check if the table has a column for that entity (e.g., "Name").
  - **If YES**, you may filter by that column.
  - **If NO**, assume the entire table belongs to that entity. **DO NOT** create a subtask to "filter by entity" if the column is missing.
  - **"Same as X" Logic:** If asking for items with the "same" attribute as X, remember to exclude X itself from the final result.

- **🔴 "How much/many" implies COUNT:** If the question asks "How much/many <Column>...", the intent is usually to **COUNT rows**, not select the column value.
- **🔴 "Nth Row/Place" implies Value:** If the question asks for the "second row" or "third place", check for a "Rank" or "Position" column and filter by value (e.g., Rank=2). Do NOT use physical index (iloc) unless no such column exists.

- **Filter before extreme values/sorting:** When searching for an entity with an extreme attribute (e.g., youngest, oldest, highest), always apply any necessary filters first to create a candidate pool, then sort or find max/min.

- **Determine deduplication intent:** Infer from the question whether DISTINCT logic is required. Default to deduplicating on the primary key when operations may produce duplicate rows.

- **🔴 CRITICAL: LIMIT 1 Semantics:** If the question asks "Which ... has the most/highest/fastest/least/oldest/lowest/largest/smallest?", the final subtask MUST explicitly specify "select only ONE result" (equivalent to `ORDER BY ... DESC LIMIT 1`).

- **Minimize returned fields:** Keep final output fields to the absolute minimum required to answer the question.

- **Ensure strict JSON compliance:** Your output must be valid JSON. DO NOT include any comments inside the JSON.
